# 决策速查表（cheatsheet）

按"遇到什么情况就怎么做"组织；一行一个判据。

## 阶段路由

| 用户带来的东西 | 先做什么 |
|---|---|
| 只有一个领域名词（"我想研究数字劳动"） | S0 先要一句困惑；给六来源扫描清单 |
| 一句话兴趣 / 草题 | 直接 S1 诊断卡 |
| 开题段落或已投稿被拒的问题 | S1 诊断 + 重点跑八种问题病 |
| "帮我把题目定下来"（催成品） | 仍逐工序出中间文本，节奏加快、不跳步 |

## 一句话判据

- 外行也能问出的问题 → 信息量不足，回炉（差异性发问）。
- 只能答是 / 否的问题 → 补差异性或改 To what extent。
- 四五个词说不清的主题 → 太宽，跑 Booth 三步。
- 问题里有"或" → 拆成两个独立问题。
- 问题里有 should / better / 更好 → 规范问题，改成事实问句。
- 职业即阶级式自含答案 → 同义反复，换问题。
- "没人做过" → 改说"位于两个未被交叉领域的新交叉点"。
- 答案人人猜得到 → 太简单，收窄到具体时代 / 类型 / 人物。
- 假说列出一大堆且性质各异 → 太发散，明确到具体案例。
- 现有理论解释不了这个案例 → 好起点，从"已知理论的缺陷在哪里"发问。
- 结论的前提已经消失（政策变了、趋势反了）→ 困惑五特征之一，值得追。
- 个人偏好问题（要不要结婚）→ 转译成公共事实问题（婚姻与健康的可比数据）。
- 解释型问题没有描述铺垫 → 先安排"正在发生什么"。
- 核心概念讲给非专业者听讲不清 → Feynman 检验不过，先补概念功课。
- 定性问题的范式—视角—传统像缝合怪 → 对齐检查，重配部件。
- 做不了纵向 → 改横断面比较；1 小时访谈 ≈ 8 小时转写，先算转写账。
- 设计做不了 → 改问题（减问题数或改关键术语），不硬扛。

## 收窄守则

- 主问题 2–3 个封顶；学位论文总共不超过 5 个。
- 子问题只留贡献型；伴生型逐个追问数据可得性。
- 每个问题内含 what / who / where / when 四要素。
- 每收窄一步，重新回答一次"这个问题需要什么数据"。

## 升级守则

- 差异句先行："什么和什么之间，在什么上的不同"，写不出就还不是差异性发问。
- 因果假说一句话 + 替代假说至少两条 + 分歧点可用证据裁决。
- 假设被默认的年头越长、越未被挑战，质疑的惊奇潜力越高。
- 质疑层级越宽冲击越大但越难做深；质量与惊奇感比范围重要。
- 每拆一个假设，必须给出替代假设地基——终点是新问题，不是新姿态。
- 三反应测试：调整"否定多少受众假设"的火候，不换立场。

## 终检红线（一票否决）

单句写得清 → 小报语言通顺 → so what 有硬答案 → 介于 obvious 与 absurd 之间 → 概念全部操作化 → 比较物齐备 → 意识形态自检五问全过。

## 交付纪律

- 每道工序产出当前版本问题句 + 改动清单 + 1–2 个留给用户的自检问题。
- 多轮迭代保留版本记录。
- 不做录用预测；刊物匹配只给三条契合线，期刊具体要求提示查当期官网。
